## Tested sources
### Google Sheet「團購記錄 - Demo Co.」(ID DEMO_GROUPBUY_SHEET_ID) via hatch_gws_cli
**Used by**: listTabs, getWeek, setPickedUp (through privileged handlers in server/src/privileged.ts, same pattern as cang-ku-cun-huo)
**Test command**: `/opt/hatch/bin/hatch_gws_cli sheets status` → connected; `sheets spreadsheets get --params '{"spreadsheetId":"DEMO_GROUPBUY_SHEET_ID"}'`; `sheets spreadsheets values get` on ranges `2026-11-23!A1:H30` and `2026-11-23!A670:H685`
**Sample output**: Workbook title「團購記錄 - Demo Co.」; tabs: 「測試週」(sheetId 865178293) and「2026-11-23」(sheetId 2127330413), both frozenRowCount 1. Header row: 訂單編號/姓名/客人備註/貨品/數量/單位/備註/已領取. Data rows confirm the model: order 1 (ଘAliceଓ) spans 2 item rows, H="FALSE" only on the first row, second row has no H cell; order 3 (Ben) carries 客人備註 2045550123 repeated per row; tail rows reach order 274, matching 261 orders / 680 rows / numbers 1–274 with gaps.
**Processing**: getWeek reads `<tab>!A1:H1200`, skips the header, groups consecutive rows by 訂單編號 (A), takes 姓名/客人備註 from the group's rows, collects items (D 貨品, E 數量, F 單位, G 備註), and reads 已領取 from H of the group's first row ("TRUE"/"FALSE" strings). setPickedUp re-reads the tab, finds the group's first row BY 訂單編號 (never by a remembered position alone), writes only that row's H cell (`<tab>!H<row>`) with TRUE/FALSE via values update RAW, then returns fresh state. Tab list comes from spreadsheets get (sheet titles), newest date-like tab first, defaulting to the latest tab.

## Long-term data behavior
- **Refresh policy**: Direct mode — every read hits the Sheet live (no local copy, no cron); a colleague editing the Sheet is visible on next load/refetch. No scheduled refresh added (user previously declined scheduled briefings, and direct mode makes one unnecessary).
- **Growth**: One new tab per week, created outside the Space (import flow); the Space discovers tabs automatically. No local DB rows are written by the Space at all.
- **Ordering**: Orders sorted by numeric 訂單編號 ascending within a week, matching the Sheet.
- **Time semantics**: Tab titles are week dates (e.g. 2026-11-23); no timestamps are stored by the Space — 已領取 state lives only in the Sheet's H column.
- **Filtering (2026-11-21 edit, per user request)**: Purely client-side over the already-loaded week's orders — no new actions or Sheet reads. Tapping an item's product name on a card toggles that product as a filter; a「按貨品篩選」panel offers the same multi-select over all distinct products of the week (with per-product order counts). Multiple selected products combine with OR (order shows if it contains any selected product) and stack with the text search and the 全部/未領取/已領取 status filter. Selected filters show as removable chips with a 清除全部 reset; switching week clears them.
- **Number search (2026-11-21 edit, per user request)**: A second search input matches 訂單編號 only (substring), with a numeric keyboard on phones — typing "24" at the counter finds order #24 instead of every product whose name contains digits (240g, 250g…). The general search covers 姓名／貨品 only (編號 removed from it). Both searches stack with each other, the status filter, and the product filters; switching week or the empty-state reset clears both. Layout (2026-11-21 edit, per user request): the two inputs sit side by side in one row — the number input is narrow (fixed ~6rem, digits only), the 姓名／貨品 input takes the remaining width.
- **Selected-product pending totals (2026-11-21 edit, per user request)**: Purely client-side over the loaded week's orders — no new actions or Sheet reads. When one or more products are selected as filters, a summary panel above the order list shows each selected product with the total quantity still to hand out: the sum of that product's 數量 across 未領取 orders only (regardless of the status filter currently shown), grouped by 單位, plus the count of unpicked orders containing it. The two searches still apply; the status filter does not narrow the total, so the figure always answers "揀咗呢樣，未領取仲有幾多". Marking an order picked up updates the totals immediately via the existing optimistic update.
- **Hint copy (2026-11-21 edit, per user request)**: The per-card hint sentence「撳貨品名可以即刻用嗰樣貨篩選，再撳多次取消。」was removed from the order cards — the user wants no explanatory text on the interface. The tap-to-filter behaviour itself (item names stay tappable buttons, selected product highlights) is unchanged.
- **Customer filter (2026-11-23 edit, per user request「撳卡片上個客人名嘅時候可以淨係顯示依個客人所有單」)**: Purely client-side over the loaded week's orders — no new actions or Sheet reads. Tapping the customer name on a card filters the list to orders whose 姓名 exactly equals that name (exact match, so one customer's orders never pull in another with a containing name); tapping the same name again clears it. The active customer shows as a removable chip above the list; the filter stacks with both searches, the status filter, and the product filters, and clears on week switch and via the empty-state reset.
- **Reload feedback (2026-11-23 edit, per user request「加返個回饋，載入嗰陣轉做『載入緊…』」)**: Purely client-side — no new actions or Sheet reads. The「↻ 載入」button tracks its own manual refetch: on tap it disables, shows「載入緊…」, and awaits both the weeks list and the current week queries before restoring「↻ 載入」. Previously the button gave no feedback at all, so a reload with unchanged Sheet data looked like a dead tap.
- **Pickup date-time (2026-11-23 edit, per user request「團購已取可唔可以記埋日期時間？」)**: Column I「領取日期時間」was added to the Sheet (header verified live on both tabs「測試週」and「2026-11-23」on 2026-11-23; existing rows have no I values yet). setPickedUp now writes H and I together on the group's first row (`<tab>!H<row>:I<row>`): marking picked up stores the current Winnipeg date-time as "YYYY-MM-DD HH:mm"; marking back to not picked up clears I. If a future tab lacks the I1 header, setPickedUp writes the header first. getWeek returns `picked_at` per order (empty for orders ticked before timestamps existed — never backfilled with invented times), and picked-up cards show「領取時間：…」under the name. Reads widened to A1:I2000; layout assertion still anchors on A–H and only rejects a *different* non-empty I header.

## Rejected approaches
- **Tried**: Local DB mirror with sync (the old warehouse Space pattern)
  **Why rejected**: The warehouse Space was deliberately converted to direct Sheet mode by the user; a mirror risks divergence when a colleague edits the Sheet directly, and pickup ticking must be right at the counter.
- **Tried**: Writing H on every row of an order group
  **Why rejected**: The Sheet's established convention (set by the import) is checkbox only on each group's first row; writing extra cells would diverge from how the Sheet is maintained.

Imagery not needed: this is a counter checklist tool; orders are text (names, items, quantities) and photos would slow down pickup lookup.
